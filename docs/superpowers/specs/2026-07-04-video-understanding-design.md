# InspoClip 视频理解功能设计

## 1. 目标与范围

InspoClip 新增产品/UI 动效演示视频理解能力。首期支持 10 秒至 2 分钟、最大 200 MB 的单个视频，识别完整内容、界面状态变化、交互触发、分阶段动作、转场节奏和视觉风格，并生成可复刻视频效果的提示词或实现规格。

客户端和浏览器插件均支持视频上传与分析。默认视频模型为 `qwen3.7-plus`，用户可在客户端设置中修改模型及连接配置。首期不建设通用视频管理、视频编辑、长视频内容平台或实时视频分析能力。

## 2. 核心决策

- 使用数据库驱动的异步任务，不在上传请求中同步等待模型结果。
- 使用 LangChain 重构现有图片模型调用，并承载新增视频模型调用。
- 业务代码只依赖项目自有的模型接口，LangChain 类型不得扩散到路由、数据库和前端协议。
- 使用统一视频分析结果作为事实来源，再按用户选择的用途生成不同输出。
- 默认用途为“通用”，且用途选择器始终包含“通用”选项。
- 每个实现阶段验证通过后提交到 `develop`；未经用户明确确认不得执行 push。

## 3. 系统架构

视频处理链路：

1. 客户端或插件上传视频。
2. 服务端校验 MIME、扩展名、文件大小和时长，保存文件并创建视频记录。
3. 服务端创建待处理任务并立即返回任务 ID。
4. 内置任务执行器领取任务，将视频提交给 Qwen。
5. Qwen 返回结构化视频理解结果，服务端校验并持久化。
6. 用户选择输出用途，服务端根据标准分析生成或读取对应提示词。
7. 客户端轮询任务状态并展示播放器、阶段时间线和输出内容。

首期任务执行器随 Express 服务运行，数据库承担队列和恢复职责。未来可在不改变 API 的前提下迁移到 Redis/BullMQ。

## 4. AI 调用架构

后端 AI 层拆分为以下边界：

- `ModelConfigService`：读取并合并图片与视频模型配置，默认视频模型为 `qwen3.7-plus`。
- `ModelProvider`：项目自有接口，定义文本、图片和视频请求能力。
- `LangChainProvider`：处理 OpenAI 兼容模型，支持透传 `video_url`、`fps` 等供应商参数。
- `GeminiProvider`：仅在 LangChain 无法完整表达 Gemini 视频参数时使用原生 SDK/HTTP。
- `PromptService`：集中管理图片术语、图片设计提示词、视频分析和用途转换 Prompt。
- `StructuredOutputParser`：校验模型 JSON；首次失败时执行一次修复，仍失败则保留原始响应并将任务标记为失败。

现有图片分析迁移到新架构，但保持现有 HTTP API、返回结构和用户行为不变。

## 5. 数据模型

### 5.1 videos

- `id`
- `file_path`
- `thumbnail_path`
- `original_name`
- `mime_type`
- `size_bytes`
- `duration_ms`
- `width`
- `height`
- `source`：`client` 或 `extension`
- `created_at`

### 5.2 video_analysis_jobs

- `id`
- `video_id`
- `status`：`pending`、`processing`、`completed`、`failed`
- `progress`
- `model`
- `fps`
- `attempt_count`
- `error_message`
- `raw_response`
- `started_at`
- `completed_at`
- `created_at`

服务启动时将遗留的 `processing` 任务恢复为 `pending`。任务因限流或瞬时网络错误失败时采用有限次数指数退避；永久错误直接失败。

### 5.3 video_analyses

- `id`
- `video_id`
- `summary`
- `visual_style`：JSON
- `analysis`：完整标准化 JSON
- `created_at`
- `updated_at`

### 5.4 video_prompt_outputs

- `id`
- `analysis_id`
- `purpose`
- `target`
- `locale`
- `content`
- `created_at`
- 唯一键：`analysis_id + purpose + target + locale`

## 6. 标准视频分析结构

```json
{
  "summary": "视频整体内容与交互目标",
  "visualStyle": {
    "colors": [],
    "typography": "",
    "layout": "",
    "effects": []
  },
  "stages": [
    {
      "startTime": 0,
      "endTime": 1.8,
      "title": "首页进入",
      "initialState": "初始界面状态",
      "trigger": "页面加载",
      "actions": [
        {
          "subject": "主标题",
          "action": "淡入并上移",
          "from": {},
          "to": {},
          "durationMs": 600,
          "delayMs": 120,
          "easing": "ease-out"
        }
      ],
      "resultState": "阶段结束后的界面状态"
    }
  ],
  "assets": [],
  "uncertainties": []
}
```

每个阶段必须描述 `initialState → trigger → actions → resultState`。无法可靠识别的细节必须进入 `uncertainties`，不得编造精确参数。

## 7. 输出用途

用途选择器包含：

- 通用复刻提示词（默认）
- 视频生成：支持 Sora、Veo、即梦等目标模板
- 前端实现：React、CSS、Framer Motion 等实现规格
- 动效工具：After Effects、Figma 动效规格
- 分镜脚本
- 结构化 JSON

所有用途共享同一标准分析，不重新分析视频。首次选择某个用途时生成并缓存结果；再次访问直接读取缓存。用户修改目标平台或语言时生成新的缓存项。

通用输出必须包含整体目标、视觉风格、分阶段动作、时序节奏、资产描述、复刻约束和不确定项，不绑定具体工具。

## 8. 服务端 API

- `POST /api/videos`：上传视频并创建分析任务。
- `GET /api/videos/:id`：读取视频元数据、分析状态和已有结果。
- `GET /api/video-jobs/:id`：读取任务状态与进度。
- `POST /api/videos/:id/retry`：重试失败任务。
- `GET /api/videos/:id/analysis`：读取标准分析。
- `POST /api/videos/:id/prompts`：按用途、目标和语言生成提示词。
- `GET /api/videos/:id/prompts`：读取已生成输出。
- `DELETE /api/videos/:id`：删除视频文件、任务和分析数据。

配置接口增加独立的视频模型键：供应商、API Key、API Base、模型 ID 和默认 FPS。API Key 仅接受写入，读取时返回掩码，不得返回明文。

## 9. 客户端交互

- 上传入口接受图片和视频，并按 MIME 类型分流。
- 视频上传前显示文件名、大小、时长与预览。
- 上传后显示上传中、等待处理、分析中、生成结果、完成或失败状态。
- 结果页包含视频播放器、可点击阶段时间轴、阶段动作详情、用途选择器和输出复制操作。
- 点击阶段时播放器跳转到对应开始时间。
- 默认用途为“通用”。切换用途后异步生成或加载对应内容。
- 失败状态显示可理解的错误和重试入口。
- 设置页分别呈现图片模型和视频模型配置，避免改变现有图片分析行为。

## 10. 浏览器插件交互

- 为网页 `<video>` 元素增加“保存并分析视频”右键菜单。
- 插件弹窗支持选择本地视频或粘贴可访问的视频 URL。
- 后台脚本负责下载可访问视频并上传服务端。
- 对鉴权资源、跨域资源和 Blob URL，下载失败时提示用户先保存到本地再上传。
- 插件显示上传和分析状态以及最终摘要。
- 完整播放器时间线、用途切换和提示词结果通过“在 InspoClip 中查看”跳转主客户端。
- 插件只保存服务器地址，不保存模型 API Key。
- 视频逻辑拆分为独立模块，避免继续扩大现有 `content.js` 的职责。

## 11. 安全、限制与清理

- 首期限制：时长 10 秒至 2 分钟，大小不超过 200 MB。
- 允许格式：MP4、MOV、WebM；服务端同时检查扩展名、声明 MIME 和实际媒体信息。
- 上传文件使用服务端生成的文件名，不信任原始路径或文件名。
- 视频静态访问路径不得允许目录穿越。
- 删除视频时同步删除视频文件、缩略图和关联数据。
- 模型错误日志不得记录 API Key；原始响应需限制长度并避免包含敏感配置。

## 12. 测试与验收

### 自动测试

- `ModelProvider` 契约测试和 LangChain 适配器测试。
- 图片分析迁移回归测试。
- 视频上传格式、大小、时长校验测试。
- 任务状态转换、重试和服务重启恢复测试。
- 标准分析 Schema 与异常 JSON 修复测试。
- 用途生成、默认通用用途和缓存唯一性测试。
- 客户端上传、轮询、失败重试、阶段跳转和用途切换测试。
- 插件普通 URL、本地文件、Blob URL 和跨域失败路径测试。
- 所有 AI 测试使用假模型，不依赖真实 Qwen API。

### 人工验收

使用至少三段 UI 动效视频覆盖页面进入、点击交互和复杂转场：

- 能完整描述视频目标和阶段顺序。
- 阶段时间区间覆盖视频主体且不存在明显重叠错误。
- 每个阶段包含初始状态、触发、动作和结果状态。
- 默认显示通用复刻提示词。
- 切换用途不会重新执行视频分析。
- 客户端和插件均可启动分析并查看最终状态。
- 现有图片上传、术语生成和设计提示词功能保持可用。

## 14. 日期卡片视频归档补充设计

- 移除客户端独立悬浮“分析视频”入口，统一使用日期卡片上传区和页面粘贴。
- 日期卡片上传区同时接受图片与视频；视频记录 `weekId`、`dayOfWeek` 和 `sortOrder`，页面粘贴的视频归档到当天。
- 周数据接口同时返回图片和视频，并附带视频最新分析任务状态。
- 视频卡片沿用现有纸张卡片的边框、阴影、圆角、字体和强调色，展示缩略图、时长及分析状态。
- 点击视频卡片进入完整分析视图；失败状态允许重试，卡片允许删除。
- 首期图片仍可独立拖拽排序，视频不参与图片与视频的混合排序。
