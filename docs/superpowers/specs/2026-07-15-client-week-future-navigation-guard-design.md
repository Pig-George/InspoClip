# 客户端周视图未来周切换守卫设计

## 背景

周视图在当前周时，下一周按钮通过原生 `disabled` 表现为不可用，但键盘右方向键仍会直接执行周切换，从而进入未来周。同时，原生禁用按钮不会派发点击事件，无法在用户继续点击时提供抖动反馈。

## 目标

- 周视图不得通过按钮或键盘快捷键进入未来周。
- 当前已是本周时，继续点击下一周按钮需要播放短促抖动动画。
- 键盘右方向键触发同一切换守卫，并提供一致的受阻反馈。
- 保持现有按钮禁用视觉和其他视图的键盘行为不变。

## 方案

在 `App` 中建立单一的下一周切换入口 `attemptNextWeek`：

1. 比较当前周一与今天所在周的周一。
2. 当前周早于本周时，正常切换到下一周。
3. 当前已是本周或意外处于未来周时，不更新日期，只递增一次“受阻尝试”信号。
4. 周视图按钮和键盘右方向键均调用该入口，避免两套边界判断产生差异。

`WeekHeader` 接收是否可前进和受阻尝试信号。下一周按钮不再使用原生 `disabled`，改用 `aria-disabled`、禁用样式和统一切换回调，使按钮仍可接收点击并播放反馈。每次受阻信号变化时，按钮执行一次约 250ms 的水平抖动并回到原位。

## 交互与可访问性

- 不可前进时继续使用现有低透明度视觉，并去除可操作态 hover 反馈。
- 保留按钮语义，使用 `aria-disabled="true"` 向辅助技术表达不可用状态。
- 受阻反馈采用“轻触回弹”：水平位移关键帧为 `[0, -2.4, 1.2, -0.4, 0]`，总时长约 380ms，并辅以 `1 → 0.985 → 1` 的轻微缩放。
- 动画使用柔和的 cubic-bezier 缓动，前段表达碰到边界，后段逐步衰减回到原位，避免快速对称抖动带来的机械感。
- 位移与缩放仅作用于下一周按钮，避免影响周标题和其他操作按钮布局。
- 启用减少动态效果偏好时，不执行位移动画，但仍阻止未来周切换。

## 边界

- 当前周：按钮点击和键盘右方向键均不改变日期。
- 历史周：按钮点击和键盘右方向键均可前进一周，最多回到当前周。
- 未来周：若旧状态或外部状态导致日期已在未来，继续前进仍被阻止。
- 日视图和时间轴视图的现有导航逻辑不在本次范围内。

## 测试

- 单元测试周导航判断：历史周允许前进，当前周和未来周禁止前进。
- 组件测试下一周按钮：当前周具有 `aria-disabled`，点击仍发送受阻尝试但不执行日期更新。
- 快捷键回归测试：当前周按右方向键不会进入未来周；历史周仍可正常前进。
- 验证客户端完整测试集和生产构建。
